## 学习目标

学完后应能：

1. 解释网络为什么要分层：它解决什么复杂度问题，一层换实现时为什么不必改掉整栈。
2. 用自己的话说明 TCP/IP 四层各自解决什么问题，并能指出 HTTP、TCP、IP、以太网大致落在哪一层。
3. 以「浏览器访问一个网页」为例，讲清发送端如何逐层封装、接收端如何逐层解封装，以及每一层头部主要在标识什么。
4. 对照 OSI 七层，说明常见对应关系，并分清「这是模型」和「这是某台机器上真实跑着的协议」。
5. 能处理典型边界：路由器转发时通常剥到哪一层、为什么应用一般不用自己管 MAC 地址。

```text
核心概念
├── 基础概念
│   ├── 协议：双方约定的规则
│   ├── 分层：把通信问题拆成可替换的几层
│   └── 协议栈：一台主机上各层协议的组合
├── 核心原理
│   ├── 每层只通过接口使用下层，不关心下层怎么实现
│   ├── 对等层：两端同一层在「逻辑上」对话
│   └── 上层数据对下层通常只是 payload
├── 关键机制
│   ├── 封装：下行时各层加头（链路层还可能加尾）
│   ├── 解封装：上行时各层剥头、交给上一层
│   └── PDU 名称：报文 / 段（或数据报）/ 包 / 帧
├── 重要组成部分
│   ├── 应用层：HTTP、DNS 等，给用户程序用
│   ├── 运输层：进程到进程（端口），TCP / UDP
│   ├── 网络层：主机到主机（IP 地址），跨网转发
│   ├── 网络接口层：链路上相邻节点（MAC 等）+ 物理比特
│   └── 与 OSI：7 层如何大致映射到这 4 层
├── 相关概念
│   ├── 端到端（运输层）vs 逐跳（网络层、链路层）
│   └── 端口 / IP / MAC 分别回答「谁、哪台、哪一跳」
├── 常见应用
│   └── 浏览器请求网页：HTTP → TCP → IP → 以太网
└── 常见问题
    ├── 「HTTP 到底第几层」取决于用哪张模型图
    ├── 路由器为什么通常只看到网络层及以下
    └── 换网卡、换路由、换应用协议时，哪些层要动
```

## 重点划分

### Core

必须掌握，验收必查：

- 分层要解决的问题：隔离变化、约定接口、让不同厂商/协议能互操作
- TCP/IP 四层各自的职责，以及 HTTP / TCP / IP / 以太网的归属
- 封装与解封装的方向和过程（用一次网页请求讲完）
- 端口、IP、MAC 分别属于哪一层、各解决什么定位问题
- 路由器转发时大致剥到哪一层、为什么不是剥到应用层

### Important

应该理解：

- OSI 七层与 TCP/IP 四层的常见对应（尤其会话/表示层常被「吃进」应用层）
- PDU 常用叫法：段、包、帧分别在哪一层
- 「对等层通信」是逻辑上的，物理上数据仍要走到最底层才出门
- 主机 vs 路由器：谁跑满栈、谁主要跑下面几层

### Optional

了解即可，不阻塞当前目标：

- OSI 的历史和各层标准细节
- TCP 三次握手、滑动窗口、重传
- IP 分片、子网、CIDR、路由算法
- 以太网帧字段、MTU、ARP 的完整机制
- 五层模型与四层模型的叫法之争
